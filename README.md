# Portiva 2

使用 Rust + GPUI 重建 Portiva 的 SSH / SFTP 工作台，并提供应用内本地终端。核心服务可独立于桌面界面构建和测试。

## 获取源码

```sh
git clone https://github.com/gshu55/Portiva2.git
cd Portiva2
```

## 运行

Windows 需要 Rust MSVC 工具链和 C++ Build Tools。项目通过 `rust-toolchain.toml` 固定 Rust 1.100.0，通过 `Cargo.lock` 固定依赖。

```powershell
.\build.cmd -Run
```

统一构建入口为 `build.cmd`（调用 `scripts/build.ps1`），日常开发默认 Debug，始终输出 `dist\portiva2.exe`；以后直接运行这个固定路径。再次构建会替换同名程序，并清理 `target\debug`、`target\release` 和 `dist` 顶层旧的 `portiva2-settings`、`portiva2-ui-preview` 等改名产物；Cargo 依赖缓存仍保留在 `target`。启动器仅为当前构建进程使用 `RemoteSigned` 运行本地脚本，不修改系统执行策略。

```powershell
# 只构建最新版本
.\build.cmd
# 正式优化构建，仍然使用同一个输出文件名
.\build.cmd -Configuration Release
# 依赖已缓存时可离线构建
.\build.cmd -Offline
```

Windows 的 Debug / Release 程序均使用图形应用入口，直接启动 `dist\portiva2.exe` 不会附带命令行黑窗口。`build.cmd` 的构建输出仍显示在当前命令行中，`-Run` 在构建成功后正常打开应用窗口。

更新前先关闭正在运行的 Portiva 2；如果程序占用导致无法覆盖，脚本会报错并保留已有程序，不自动结束 SSH 会话或改名生成另一份。构建或复制失败也会保留原来的输出。`cargo run -p portiva-desktop` 仍可用于源码调试，但交付和日常启动统一使用 `dist\portiva2.exe`。

默认配置保存在 Windows `%APPDATA%\Portiva2`；其他平台为 `$HOME/Portiva2`。开发时可以使用工作区内的独立数据目录：

```powershell
$env:PORTIVA2_DATA_DIR = Join-Path $PWD.Path '.local/app-data'
.\build.cmd -Run
```

Linux / macOS Apple Silicon 的源码运行入口如下；平台分支已经实现，尚未在对应平台完成编译与运行验证：

```sh
cargo run -p portiva-desktop --locked
```

点击顶部“+”，填写主机、用户名和认证方式。主机概览点击已保存主机直接打开连接；编辑使用主机右侧的铅笔图标。保存过的凭据自动复用；没有保存密码时在连接标签内补输本次密码，不弹出完整编辑框。首次连接仍需核对主机指纹。可选择私钥文件，并勾选“记住密码 / 口令”；密码和私钥口令通过 `keyring` 保存在当前系统用户的凭据库，连接 JSON 不包含明文秘密，私钥保留原文件路径。不同配置目录、服务器、用户和私钥路径的凭据相互隔离。旧版配置和凭据暂未自动导入。

## 已实现

- 界面：参照原版的中性深色与蓝色强调色，自绘顶部会话/设置标签、图标工具条、拖动区域和窗口控制；主机概览只提供 SSH / SFTP，设置采用左导航和居中卡片，连接弹窗采用双列排布。
- 连接：密码、私钥与 SSH Agent 接口，多会话标签，连接状态，指纹确认与持久化，指纹变化拒绝连接，连接取消。
- 本地终端：顶部终端图标在应用内打开本地标签，沿用终端配色、背景、复制粘贴与分屏。Windows 使用 PowerShell 7 → Windows PowerShell → CMD；Linux/macOS 使用 `$SHELL`，不可用时读取账号默认 Shell，再回退 `/bin/sh`。终端按当前进程权限运行，底部不显示程序路径或当前目录。Linux/macOS 平台分支已实现，尚未完成实机编译与运行验证。
- 标签：空间充足时全部展开标题，放不下时才将未选中的标签收缩为图标，选中标签保持展开；关闭标签或加宽窗口后自动恢复。SSH 标签随当前聚焦分屏上报的任务标题更新，切换分屏及关闭补位同步更新；空标题、Shell、目录或登录默认标题保留连接名称，悬停同时显示任务与主机信息。任务名称来自远端 OSC 0/2 标题，不从终端输出猜测或向服务器安装脚本。继续超出顶部空间时支持鼠标滚轮和触控板水平滚动，不绘制滚动条。新建和切换自动定位选中标签，鼠标中键可关闭会话与设置标签；主机概览作为固定入口保留。
- 终端：真实 SSH PTY、窗口尺寸同步，支持对当前终端左右、上下嵌套拆分和拖动分隔条；每个分屏使用独立通道，关闭时自动补位，至少保留一个终端。Alacritty 解析支持 ANSI / 256 色 / 真彩色、中文和宽字符、历史滚动、鼠标选择、复制粘贴、特殊按键和括号粘贴。输入法预编辑与提交分开处理。
- 内容高亮：SSH 与本地终端支持 `cat`、`tail`、`tail -f/-n`、`head`、`Get-Content` 等普通输出的本地显示配色，无需服务器安装插件。日志区分错误、警告、提示、成功和调试，支持常见时间戳、括号级别、中文与缩进续行；代码复用 Syntect 语法，区分 HTML 标签/属性、CSS、C# 类名/函数名、关键字、字符串、注释等，另支持 JavaScript、JSON、Rust、Python、Shell。设置 → 终端 → 内容高亮可分别开关，并自动识别或指定语言，立即生效、自动保存。只覆盖默认前景色，保留程序显式 ANSI / 真彩色、选区和背景；全屏应用沿用自身配色。自动识别结合文件名、代码围栏和内容特征，不等同于完整的语言语义分析；上下文较远或识别不准时可指定语言。
- CLI 文本交互：标准 `Ctrl+Shift+C/V`、`Ctrl+Insert`、`Shift+Insert` 始终保留，可另设自定义快捷键；`Shift+Enter` / `Alt+Enter` 可向交互式程序发送不同的换行按键。应用开启鼠标追踪时仍可使用 Portiva 右键菜单、按住 Shift 拖选，完成的选区保留文本快照以供界面重绘后复制。支持当前活动窗口中聚焦终端的 OSC 52 文本复制请求；不响应程序读取本机剪贴板的请求。多行确认设置继续生效；程序启用括号粘贴时，大段内容作为单个粘贴事件发送。
- 长输出：保留最多 50,000 行滚动历史，窗口变窄时由 Alacritty 重新折行，复制软换行不插入额外换行符；同一行同样式的 ASCII 文字批量排版，中文、宽字符和组合字符仍按网格定位。支持触控板细小滚动累积、拖选至边缘自动翻页、全屏程序滚轮转方向键，以及返回最新输出的图标。
- 文件：SSH 旁的 SFTP 面板首次默认收起；显示状态、左右位置和栏宽自动保存，新连接和重启后恢复上次布局。现有连接各自保留当前目录、选择、布局和传输状态；本地/远端双栏同样支持换位。列表复用 GPUI Kit 内置的 Lucide 图标，区分文件夹、链接、普通文件及文档、代码、配置、脚本、图片、音视频、压缩包和表格，统一尺寸和主题色。导航、刷新、上传下载、新建目录、重命名和删除统一使用带中文悬停说明的图标按钮。支持路径输入、进入和返回目录、Ctrl / Shift 多选及删除确认。
- 传输：文件、多文件、递归目录上传下载，三个并行任务槽，进度、暂停/继续、取消、失败重试、覆盖/跳过/取消冲突处理。队列由对应连接顶部的图标展开，每个连接独立显示自己的记录。
- 资源底栏：显示当前连接服务器的 CPU、内存和根分区磁盘占用；Linux 资源通过独立 SSH exec 通道读取，每 3 秒采样，只轮询当前可见连接。首次 CPU 采样、采集失败或数据过期时显示未获取状态；失败后等待 30 秒再试。设置自动保存状态由设置页和顶部设置入口反馈。
- 文件落盘：临时文件传输后提交，上传覆盖时保留原文件以供提交失败回滚，下载路径校验与已有链接/目录联接检查，跳过递归传输中的链接和特殊文件。
- 设置：界面深色、浅色、跟随系统；极光/远山/等高线与本地背景图导入、强度和模糊滑块；字体下拉列表读取系统实际安装的字体并支持搜索，跨平台找不到原字体时优先回退到已安装的等宽字体；字号直接输入数字，默认 14，不显示单位；旧版深浅色与 Dracula 预设、20 项颜色选择器；右键菜单/粘贴/智能复制粘贴/关闭；多行粘贴编辑确认；自定义复制、粘贴、新建连接和设置快捷键。有效修改立即作用于现有会话并自动保存，重启后保留；连续调整会合并写入，关闭设置标签仍会保存最后的修改。无效或未完成的文本保留上次有效值，并在对应输入框下提示；切换会话和主机概览会保留输入内容及滚动位置。设置中不再单列凭据页，记住与忘记凭据仍在连接编辑框操作。

SSH 终端默认使用 `Ctrl+Shift+C` / `Ctrl+Insert` 复制选择、`Ctrl+Shift+V` 或 `Shift+Insert` 粘贴、`Ctrl+Shift+A` 全选输出、`Shift+PageUp/PageDown` 按视口翻页、`Ctrl+Shift+Home/End` 到历史顶部/最新输出。沿用旧版：有选区时 `Ctrl+C` 复制，无选区时中断远端程序；该行为可关闭。右键默认打开复制、全选、粘贴菜单，可在设置中改为其他行为。`Tab` / `Shift+Tab` 发送到远端 Shell 或终端应用，命令和路径补全取决于远端 Shell 配置。macOS 同时支持 `Cmd+C/V/A`。

从顶部齿轮或 `Ctrl+,` 打开设置，`Ctrl+N` 新建连接，`Esc` 关闭空闲连接弹窗。新建连接的可见入口统一为顶部“+”；顶部终端图标打开本地终端。SSH 连接页顶部提供双栏文件/终端、SFTP 收起与左右换位、左右/上下拆分和当前连接传输队列图标，悬停可查看说明。每个终端标题栏右侧的关闭图标只关闭该分屏，最后一个终端的按钮禁用；关闭未聚焦分屏保持当前终端和焦点。点击终端正文或标题选择当前分屏，以主题色标题、淡色标题栏和小标记区分操作目标。主机概览编辑框的删除配置操作采用垃圾桶图标。SFTP 换位、收起和文件模式切换保留终端分隔条尺寸。文件列表双击目录进入，双击普通文件发起传输。在双栏模式下，传输目标是另一栏当前目录；终端模式下载会打开本地目录选择器。

连接弹窗的主机输入占满整行，输入框使用细边框；SSH / SFTP 的选中边框与底色在悬停时保持。底部保存、保存并连接采用与工具栏一致的图标按钮，悬停显示操作名称。界面与主机指纹字体跟随系统，文件选择器在界面线程创建异步对话框，再由后台处理结果。

“暂停/继续”保留当前任务的进度；“重试”创建一个从头执行的新任务，并再次处理冲突。传输记录目前不跨应用重启恢复。用户主动取消时会尝试清理临时文件；网络断开或进程被强制结束可能留下 `.part` / `.backup` 文件。

全局背景图由工作台统一绘制，SSH 终端、本地文件和 SFTP 内容区不再叠加底色，背景强度与模糊效果和设置页一致。关闭背景图后，终端恢复所选配色的底色，文件面板恢复界面主题底色。独立 SFTP 连接仍直接打开双栏文件；双栏模式不会覆盖 SSH 旁 SFTP 面板的显示偏好。

## 分层

```text
portiva-desktop                     portiva-core
GPUI 工作台 / 连接表单               连接配置 / 主机信任
终端 Canvas / 平台 IME       ───▶    SSH 会话 / PTY 通道
虚拟文件列表 / 系统文件选择          SFTP 浏览 / 文件操作
传输队列 / 冲突对话框        ◀───    递归任务 / 并发与取消 / 终端模型
                           CoreEvent + 普通 Rust 数据
```

`portiva-core` 没有 GPUI、Tauri 或窗口依赖。Tokio 负责网络与文件任务；界面使用显式传入的运行时句柄启动任务，把完成结果交回 GPUI 所属窗口。终端输出传递原始字节，解析和特殊按键编码在核心库完成，GPUI 负责绘制、焦点、鼠标坐标与系统输入法适配。

| 模块 | 职责 |
| --- | --- |
| `crates/portiva-core/src/model.rs` | 连接、文件、传输及事件模型 |
| `client.rs` | SSH 认证、指纹确认、PTY、独立 SFTP 通道与文件操作 |
| `local_terminal.rs`（核心） | 本地 Shell 选择、跨平台 PTY、输入输出、尺寸、退出与取消清理 |
| `terminal.rs` | 无界面的 Alacritty 状态、渲染快照、按键/粘贴编码与选择 |
| `terminal_highlight.rs` | 无界面的日志识别、语法解析与按终端调色板生成高亮范围 |
| `transfer.rs` | 递归规划、并发、进度、冲突和文件提交 |
| `store.rs` / `files.rs` | 原子 JSON 存储、本地目录和路径校验 |
| `settings.rs` / `secrets.rs` | 可移植设置、调色板、快捷键校验 / 系统凭据库适配 |
| `settings_autosave.rs` | 合并连续设置编辑、串行原子保存，独立于设置页生命周期 |
| `resources.rs` | 独立 SSH exec 采样、CPU 差值、内存/磁盘解析与超时控制 |
| `crates/portiva-desktop/src/app.rs` | 会话工作台、业务入口和对话框编排 |
| `chrome.rs` / `assets.rs` | 自绘顶部栏、主机概览 / 按需打包图标 |
| `local_terminal.rs`（桌面） | 本地终端标签与工具栏 |
| `terminal_layout.rs` / `session.rs` / `resource_bar.rs` | 无窗口依赖的布局树 / 分屏与会话工具栏 / 资源底栏及轮询 |
| `connection.rs` / `files.rs` / `terminal.rs` | 各自的 GPUI 控件及交互 |
| `jobs.rs` | Tokio 任务与 GPUI 窗口的桥接 |
| `settings.rs` / `theme.rs` | 设置界面、背景图处理 / 动态界面主题 |

浏览和每个传输任务分别使用 SFTP 子通道。终端激活前先注册消费端，以保留第一段输出；有界事件队列提供背压，界面合并事件批次后让出绘制时间。

## 验证

在仓库根目录执行：

```sh
cargo fmt --all -- --check
cargo check --workspace --all-targets --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

依赖已缓存时可给 Cargo 编译与测试命令添加 `--offline`。格式检查和 Clippy 需要对应工具链的 `rustfmt`、`clippy` 组件。

Windows x64 已通过 40 项单元与回环协议测试、Rustfmt、全目标 Clippy 和原生窗口回归。默认测试使用临时目录与本机合成服务，真实系统凭据库测试需要单独启用。完整命令、测试覆盖和原生窗口选项见 [测试与验证](docs/testing.md)。

## 后续范围

原版的标签拖动与窗口分离/合并、命令助手与完整服务器概览、终端搜索、富文本复制、文件右键菜单与拖入上传、终端分屏布局持久化、旧版配置迁移和 X11 尚待继续实现。
